# Working on EvoPolis

EvoPolis studies human behavior, learned social world models, and evolving institutions. Keep work cumulative in this repository and follow the active task in `docs/tasks/`.

- Begin with the empirical common-pool experiment in the README. Preserve the distinction between published protocol, reproduction, and original extension.
- Inspect upstream sources before implementing numerical rules. Record source versions and preserve attribution for copied or adapted code.
- Give priority to experiments, learning, and interpretable findings. Keep infrastructure proportional to the next experiment.
- Train behavioral models against human evidence. Evaluate institutional performance separately. Never select a model for making its simulated inhabitants more cooperative.
- Split interacting groups and repeat participants together. Keep final evaluation evidence out of search and tuning.
- Clearly distinguish parameter training, recurrent memory updates, and online adaptation. Do not claim learning, evolutionary improvement, or RSI without the corresponding evidence.
- Use the Linux filesystem under WSL. Profile available RAM and runtime before setting budgets; support checkpointing for substantial runs.
- Follow ordinary permission and access controls. Do not weaken them or request unrelated credentials. Continue through reversible work and actions already authorized in the active task.
- Protect existing user changes. Confirm `origin` points to `ReloadLightly/evopolis` before pushing; never force-push or publish to another repository.
- Keep the README centered on the scientific question, methods, actual results, limitations, and figures. Put operational detail in task notes rather than accumulating milestone logs.
- Apply the user's Final Fantasy V-inspired 16-bit visual theme across graphics and future interfaces. Follow `docs/VISUAL_STYLE.md` and the reusable `docs/assets/evopolis-theme.css`: lush pixel-art worlds, original resident sprites, silver-edged blue panels, and readable research labels. Preserve numerical values and chart geometry when restyling results.
- Update status statements when capabilities exist. Concept art and architecture diagrams are not experimental evidence. Never fabricate metrics, learning curves, or claims of successful reproduction.
- Validate consequential numerical behavior and reproducibility. Avoid tests that only mirror trivial implementation or inflate test counts.
- When the active task authorizes completion and publication, commit and push the resulting work after verification. If access is unavailable, preserve the completed work and report the specific blocker.
